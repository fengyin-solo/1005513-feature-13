# 制药企业洁净区与批生产记录管理平台

面向洁净区环境监测、批生产记录编录、物料放行、偏差与变更控制、灭菌与清洁验证、成品检验与年度质量回顾的一体化药品生产质量管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

业务规则冒烟测试（不依赖浏览器，用 esbuild 即时转译后在 node 里跑）：

```bash
cd frontend
npm test
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `pharma-cleanroom:entries` 这一项，或调用 `resetModule(模块)`。

## 成品检验分册外发规则

成品检验（`finishedqc`）在通用清单能力之上，另有一组业务规则，集中在
`src/api/qc-service.ts` 与 `src/api/qc-rules.ts`：

- **按产品分册**：按报告期间把终态（已合格/复检合格/不合格）且已签字的报告按产品打成一个 ZIP，
  每个产品一个分册 CSV，分册文件名与包内目录名都带「产品-出报告日」；分册只含
  检验编号、检验项目、标准规定、检验结果（另含检验人签字）。
- **无报告不发空包**：当期有批生产记录但没有终态签字报告的产品，只在包根目录放一份
  「产品-本期无报告说明.txt」，不生成空分册。
- **复检另开一栏**：不合格报告可「发起复检」，另生成 `<基础编号>-R2` 的复检记录（原报告保留），
  分册里初检、复检各自成节。
- **检验人签字**：签字只记姓名+日期、不改状态；未签字的终态报告会在打包前整体挡回。
- **状态一步步推进**：动作来源登记在 `actionSources`，未登记的线性动作默认只能从目标状态的前一步
  发起，跳级一律挡回（物料放行、年度回顾等分支动作已显式登记来源）。
- **重复打包只算一次**：打包台账存在 `pharma-cleanroom:aux`，已入包的报告行再次打包计入
  「重复」而不是新增计数。
- **结果回写留样待办**：判定到终态后按产品批号回写 `retainsample` 同批号记录的「待办事项」；
  同一基础编号的初复检结论只保留最新一条。
- **检验项目同一套**：多处文本里的项目按法定项目字典（`qc-rules.ts` 的 `LEGAL_ITEMS`）
  拆分、去重、排序归并；登记时出现字典外项目直接打回重填。
- **标准规定说了算**：判定时先按业务口径（范围、≥/≤、等值、应符合/不得检出/应为某性状等）
  比对标准规定与检验结果；比对结论与人工想判的结论矛盾时，以标准规定为准并挡回；
  口径无法比对的要求补数据后再判。
